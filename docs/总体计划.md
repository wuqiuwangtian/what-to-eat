# 总体计划与当前状态

本文件是有效范围与任务状态的权威入口。初版需求与研究报告保留调查过程，发生冲突时以本文件中的已确认决定为准。

## 已确认目标

在 GitHub 按 MIT 公开本项目自有代码与文档，交付能安装、能按说明构建的原生安卓应用。帮助选择困难用户更快决定吃什么，逐步从自愿反馈中学习，在不显著增加负担的前提下提供一般性饮食均衡建议。

用户已确认：个人业余推进、无硬截止日期；安卓原生优先；首版包含“看看这顿”和“帮我二选一”；可选自备 API；端侧生成模型后续验证。主页突出一键推荐，其他能力为次级入口。

补充依据为用户提供的两段 GPT 回答：[产品与架构讨论](https://chatgpt.com/s/t_6aeb1fb7fd3081919a6507434a559f64)、[价值驱动的数据闭环](https://chatgpt.com/s/t_6aeb1fef2100819184e387e01e455421)。建议不是实测结论，其中模型、论文与平台状态在实际采用时重新核验。

## 首版范围与验收

- 不填问卷、不登录、不配置模型也能一键推荐及换选；一次给一道菜或一餐搭配。
- 文字分析“看看这顿”：先核对识别结果、事件类型和时间，再保存；建议基于粗粒度类别，不做精确营养或健康评分。
- 两个已知菜品之间给一个建议；用户选择另行记录，不把系统输出当成偏好。
- 查看真实决策依据、明确限制、关闭学习、编辑/删除/导出记录和清除全部本地数据。
- 支持一种 OpenAI 兼容文本协议，云端默认关闭；普通推荐与换选零模型请求。
- 非目标：商家与交易、平台自动同步、跨应用 AI 自动操作、精确营养、疾病膳食、身高体重建模、强制打卡和推送。
- 默认中文、一般成年人、常见中式餐食。最低 Android 10；这属于工程起点，尚不表示所有机型已通过验证。

性能目标：就绪点击 P95 ≤ 500 ms，缓存换选 P95 ≤ 200 ms，冷启动可操作 P95 ≤ 2 s。必须在记录型号和系统的真机测量；开发电脑的耗时不替代该指标。

## 关键决策

1. Kotlin + Compose + Room；纯Kotlin核心供安卓和命令行共用，不建立另一套Python算法实现，避免策略漂移。
2. 普通推荐只读取本地结构化数据；模型做文字解析，输出必须落在已知菜品ID集合中。未来模型生成新候选需另加人工/结构化审核流程。
3. 事件明确区分展示、换选、计划、吃过、订单、喜欢、不喜欢、比较选择。换选主要影响当前会话，只有确认吃过参与近期食物类别汇总。
4. 删除和修改后从剩余记录重算，不维护无法纠正的累积画像；普通关闭应用不产生采纳或进食事件。
5. 先手工整理典型配方与粗类别；标签不是商家配方保证，不能保证过敏安全。
6. 不托管模型服务；无账号无遥测。API密钥加密保存，饮食数据库使用私有目录隔离且排除备份，当前没有数据库层加密。
7. 使用已发布且兼容的固定工具版本，不以追逐最新版增加不确定性。具体版本以构建文件与Wrapper为准。

## 效果研究与发布分开

四组对照为受约束随机、简单历史规则、同等信息直接大模型、完整轻量策略。候选、限制、历史可见性相同。主指标首次明确采纳率，辅助记录换选次数、决定耗时、实际执行及缺失反馈。

初始目标为相对随机采纳率提升15%；相对大模型提升10个百分点、换选减少20%为进阶目标，不是效果预测。正式实验前固定策略、阈值、缺失数据处理和统计分析，根据预实验计算样本量。完整策略无额外收益时优先简单方案。

“看看这顿”和“二选一”还需验证每周有效事件、自愿复用率及输入时间，防止功能产生很多数据却不能改善推荐。
