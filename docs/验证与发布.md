# 验证与发布

## 本地与CI检查

前提：JDK17、可访问Maven和Gradle发行站点。完整安卓构建还需要接受SDK许可并安装Android SDK Platform 35、Build Tools 35.0.0；通过`ANDROID_HOME`或不提交的`local.properties`指定SDK位置。

```bash
./gradlew -PcoreOnly :core:test :experiments:run --console=plain
python3 scripts/check_repository.py
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:assembleDebugAndroidTest --console=plain
```

`coreOnly`允许在没有Android SDK的电脑检查核心。合成情境输出固定时间和随机种子，仅证明可重复运行、数据链路和规则行为，不计算“采纳率”。大模型四组输出检查在应用设置里主动触发，需用户自己的模型配置与明确上传操作；不能把它当成盲测。

本地单元测试报告：`core/build/reports/tests/test/index.html`、`app/build/reports/tests/testDebugUnitTest/index.html`；Lint报告位于`app/build/reports/lint-results-debug.html`。开发APK位于`app/build/outputs/apk/debug/app-debug.apk`，使用开发签名，不能作为正式更新渠道。

## 设备操作验收

先装开发APK，使用合成输入；不要上传真实订单或截图来调试。

1. 清空安装：打开即可点“吃什么？”，出现一个餐食答案；点“换一个”使用其他候选。
2. 设置排除“鸡蛋,花生”，连续换选并查看依据；已知相关候选不得出现。实际配料仍需自行确认。
3. “看看这顿”输入“打算吃番茄炒蛋”，选择准备吃，保存。历史应为计划；不能作为吃过的近期惩罚。
4. 修改同条为吃过，时间设为当前或过去；接下来推荐要读取新数据。删除后不再受该记录影响。
5. 二选一选择两个菜，查看系统建议；不点实际选择时不产生偏好。点选择后只产生比较事件。
6. 断网：推荐、换选、分析已知菜名、记录与导出仍可使用。
7. 自备API：主动点击云端解析才请求网络。错误地址、401、限流、超时、未知ID、坏JSON均不能伪造新菜品或阻断本地主流程。
8. 关闭模型并删除密钥；检查导出没有模型配置及密钥。清除全部数据后历史和偏好归零，外部导出文件不受影响。
9. 字体放大、窄屏、旋转、返回重进、快速点击、应用重启，检查截断与状态错配。
10. 签名发行候选覆盖安装后保留记录；卸载再安装不应恢复密钥。检查云备份及厂商迁移行为。

已编写Compose设备测试，但编译测试APK不等于运行测试。可连接设备后执行：

```bash
adb devices
./gradlew :app:connectedDebugAndroidTest --console=plain
```

也可手动触发GitHub `device-tests` 工作流。模拟器通过不替代真机的冷启动及性能验收；现有一台真机之外的机型兼容性明确列为未知。

## 真机Macrobenchmark复现

使用AndroidX [Macrobenchmark](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview) 与[官方指标](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-metrics)，不再将Activity显示代理值当作应用就绪时间。模块按需通过`-Pbenchmarks`启用，常规构建不依赖测量器。

```bash
./gradlew -Pbenchmarks :app:assembleBenchmark :benchmark:assembleBenchmark --console=plain
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/run_benchmark.py --serial YOUR_TEST_DEVICE_SERIAL --output artifacts/macrobenchmark-new
```

Windows ADB从WSL调用时额外传`--adb /path/to/adb.exe`；若默认端口被模拟器服务占用，可先`adb.exe -P 15037 start-server`，再给脚本传`--adb-port 15037`。脚本自动转换本地安装与拉取路径。测量需要解锁真机、接受两个测试包的安装提示，运行时避免手动切应用。普通包`org.whattoeat.app`不清空、不参与测量；仅隔离包`org.whattoeat.app.benchmark`使用1000条合成吃过记录：冷启动只读同一份预置，热操作每轮重建。脚本校验已安装基础APK的SHA-256，相同时跳过重复安装；无法校验时正常更新。测量器为`org.whattoeat.benchmark`。二者均为开发签名，不作为试用发行渠道。

三种场景各20次，固定`CompilationMode.None`，目标包不可调试、允许shell性能分析，继承当前release配置（未启用压缩）。冷启动由Macrobenchmark停止进程，再用显式Activity与NEW_TASK/CLEAR_TASK标志启动，并等待目标界面；`am start -W`在部分系统可能早于目标进程返回，不使用它的TotalTime作为结果，仍由系统trace提取TTFD。冷启动准备阶段先让ProfileInstaller可接收shader清理广播，再由库真正停止进程。热操作每轮通过NEW_TASK/CLEAR_TASK重建Activity与记录、等待加载，保留可用热进程，不主动强停；首推测量一次，换选先在区间外推荐一次。合成数据准备不计入测量区间；没有清空系统文件缓存，也不代表所有历史规模和编译模式。

- 冷启动：`StartupTimingMetric.timeToFullDisplayMs`；通过`ReportDrawnWhen`等待本地设置及Room记录加载结束后报告完整显示。
- 首推／换选：从应用点击回调进入推荐，到结果组成进入Compose后的第二个帧边界结束异步trace。覆盖推荐计算、记录写入和Compose结果呈现的应用区间，**不包含物理触摸派发及显示屏扫描**，不能称为完整触摸到像素时间。
- P50/P95使用nearest-rank；20次的P95是第19个排序值。请求时延与`frameOverrunMs`分别报告，不能拿平均值或帧分位数代替请求P95。
- 摘要要求三种场景齐全、各至少20个有效数值，且每轮热操作恰有一段完整trace；缺失、零次、多次或失败不写成功摘要。达到所定义区间的目标，也不等于其他机型或完整触摸到像素目标已通过。

更新测量器后先用三轮预检确认执行链路；此模式只保存原始结果，不生成验收摘要，通过后换新目录执行上面的完整命令：

```bash
python3 scripts/run_benchmark.py --serial YOUR_TEST_DEVICE_SERIAL --smoke --output artifacts/macrobenchmark-smoke
```

脚本将实际安装的APK、完整日志与JSON保存到忽略的`artifacts/`，避免后续构建改变证据对应的APK。原始结果和Perfetto可能含系统信息，不直接发布；`summary.json`只保留白名单字段、样本和文件摘要。独立复核：

```bash
python3 scripts/summarize_benchmark.py artifacts/macrobenchmark-new/raw.json \
  --target-apk artifacts/macrobenchmark-new/target.apk \
  --runner-apk artifacts/macrobenchmark-new/runner.apk \
  --output artifacts/macrobenchmark-new/summary-rechecked.json
```

保存结果后可移除两个隔离包；普通版及其记录保留：

```bash
adb -s YOUR_TEST_DEVICE_SERIAL uninstall org.whattoeat.benchmark
adb -s YOUR_TEST_DEVICE_SERIAL uninstall org.whattoeat.app.benchmark
```

## 首轮真机性能与回归验收（2026-11-06）

| 场景 | P50 | P95 | 预算 | 本次所定义区间 |
| --- | --- | --- | --- | --- |
| 冷启动完整显示 | 458.5 ms | 494.8 ms | ≤2000 ms | 通过 |
| 热进程首推 | 128.8 ms | 157.4 ms | ≤500 ms | 通过 |

## 本地三策略试用工具

### 发行签名流程准备

`release-unsigned.apk`单独位于输出根目录，不在预览bundle中，不能直接安装。签名不需要修改源码或把密钥写入Gradle；维护者在仓库外生成并备份自己的长期密钥后，使用SDK Build Tools 35.0.0的工具：

```bash
zipalign -p -f 4 artifacts/preview-dev2/release-unsigned.apk artifacts/release-aligned.apk
apksigner sign --ks /secure/location/release.jks --ks-key-alias YOUR_ALIAS --out artifacts/release-signed.apk artifacts/release-aligned.apk
apksigner verify --verbose --print-certs artifacts/release-signed.apk
sha256sum artifacts/release-signed.apk
```

签名命令交互输入密码；不要把密码作为命令行明文、日志或仓库配置。正式首次签名由维护者决定并保管密钥。不同证书不能覆盖已有开发签名安装；不得为安装而提示所有者卸载丢数据。正式签名的初装/覆盖及备份恢复仍须单独验收，临时测试密钥只用于专用模拟器演练，不进入分发包。
